# 同解码器、同评价预算的序列邻域对照协议 v1

日期：2026-11-15。状态：**协议规则已定，适配器及审计实现待完成，未启动实验。** 本轮仅修改文档，不新增主方法或扩大运行矩阵。生产实现以 `95601b0383d43ae7d7e0200214043a0f1a58a288` 为锚，实际运行前必须另行冻结实现提交、输入与全部依赖哈希。

## 1. 问题与结论边界

比较固定解码器下的**候选序列访问效率**：相同完整评价预算内，受限前缀扫描与标准序列邻域访问各得到多少板材收益。不是前缀开关消融，不是PUCT消融，也不把解码器性能差异当作方法收益。

先确定三个参照。未来新方法M只有在生成规则、反馈机制、状态更新、参数、缓存接口、停止条件及相对近邻的方法差异全部写明并冻结后，才能加入协议；本轮没有定义或实现M，不能预先宣称创新。现有复杂搜索继续暂停，不作为默认处理组。

只拟定一个已知739件开发订单、seed1000的先导区组。它用于检查实施可行性及已知订单信号，不能作为独立订单验证。每个参照一次，未来M若加入则同区组全部并发参照重新执行，不能直接拿旧结果作同期对照。本轮不执行这三次拟议运行。

## 2. 三个参照的精确规则

共同固定基序列H为现有 `short_edge_sequence`：名义短边降序、名义面积降序、UID升序。H始终不变，即使发现更好布局也不替换；完整强初解仍保留Greedy与H中较好的一个。固定H不必等于该最好初解的顺序。

| 标识 | 原始候选流 | 排序与边界 |
| --- | --- | --- |
| `SINGLE` | 逐个UID生成 `(uid,) ++ H去掉uid` | 完全复用现有早期入口键：`(_part_order_bonus(uid, stage="early"), static_action_score[uid], uid)` 降序；每个UID一次。限实际零件数K=1。 |
| `INSERT` | 从H删除下标i的元素，插到删除后队列的下标j，0≤i,j<n、i≠j | 按`(|i-j|, i, j)`升序，i/j均为零基；j=n-1表示插到末尾。不是交换两件，也不只插到队首。完整序列重复交给统一准入层。 |
| `KENDALL-E` | 用决策向量a逐步从H的剩余队列取第a_i个元素，1≤a_i≤n-i+1（i从1计） | 先按`sum(a_i-1)`升序，再按整个a的字典序升序。全1向量包含H，交给统一去重。任意坐标均可变化，不偷偷限制为前K位。 |

KENDALL-E依据[BubbleSearch原文§2.2、§2.4–2.5](https://www.eecs.harvard.edu/~michaelm/postscripts/ipl2006.pdf)的决策向量及穷举次序。它是**嵌入本项目解码器的固定基序列穷举版本**，不是随机BubbleSearch、带基序列替换的版本、2021/2026 ASH整体算法或其原始排样质量复现。INSERT是明示顺序的一般单件插入参照，不声称这一截断访问次序代表所有插入搜索。

不引入随机扰动参数及调参阶段。三者都是确定性访问器；seed1000只保持既有共同构造配置。所有候选只能依赖各自已声明的序列规则；不得偷调用几何放置或完整评分挑出“更好候选”再只给它记一次评价。

INSERT按位移层、i、j懒生成；KENDALL-E按逆序层、字典序懒生成。不得先构造n²个插入候选或n!个向量后再启动计时，不得因n大而临时改成头部窗口。实现需迭代生成，避免把Python递归深度当作订单规模限制。

**重要限制：**十二次评价可能使INSERT与KENDALL-E只访问到各自的一部分相邻交换。必须报告实际位移/Kendall层与访问位置，不能把胜过这次截断访问写成胜过完整邻域、随机版本或整个文献方法类别。也不能看到结果后反转并列次序。

## 3. 同一解码器、几何与初始状态

所有参照使用同一 `OmnipotentDecoder` 实现和完全相同配置：2440×1220 mm板材、5 mm修边、6 mm刀具包络、既有旋转许可、放置模式、gamma及词典序评分。不得调整尾板计价、放宽留缝或漏件。净利用率为名义产品面积除以全部购入板材面积；留缝包络占用率另列，不能当净产品利用率或精确刀路损耗。

各运行独立创建求解器与解码器，共同执行且只执行Greedy→H两次完整初始化，保留较好完整布局为共同下界N0。两次均计入墙钟时间，但与后续预算分开登记；即使Greedy与H相同也不跳过其中一次，以保持既有缓存预热流程。除这两次外禁用额外warmstart、退火、修复、晋级补全及多模式补全。

两次初始布局均应保存，而非只保存最好者。共同初解后核对两份完整序列/布局/评分、最好初解身份、RNG与缓存状态。既有三类缓存须核对规范化键和值摘要；新增Board局部蓝图memo也须核对可达内容的规范化摘要，不使用对象地址。若只核对了键/计数，就只能声明该范围的一致性，不能声称全缓存状态相同。仪表开销也计入预算，不能为导出摘要延长时间。

每个后续候选都是完整UID排列，并调用同一个完整重放入口，从空布局开始解码，允许内部微缓存及decode缓存正常命中。不得为某一参照另开冷解码器、额外导入见证坐标或单独复用整单分数。各运行的缓存不跨参照共享。

## 4. 统一准入、去重与评价记账

主预算单位是**新的完整UID序列的一次完整重放尝试**。统一准入层对三个原始候选流一视同仁：

1. 初始化结束后，seen集合含Greedy与H两个完整UID排列；相同者只占一个seen项。
2. 每生成一个完整候选，`Q_gen += 1`，校验UID多重集、记录原始生成序号与方法坐标。
3. 若候选与seen中完整UID序列完全相同，记`Q_duplicate += 1`并跳过；摘要只作索引，最终精确比较UID元组。相同名义形状、相同板数、近似坐标或同一几何摘要都不足以合并不同UID序列。
4. 新序列准入时加入seen；检查剩余时间和额度后，在调用完整重放前原子地`Q_start += 1`。成功后才`Q_complete += 1`并保留完整布局。
5. 重放超时/异常也消耗已花的开始额度；不回滚、不重试、不用下一候选补成十二个成功结果。不允许第十三次完整重放。

不设置跨候选整单score缓存；内部decode/micro/blueprint命中不免除已开始的完整重放额度。每次完整重放都必须独立返回并验证完整结果。重复生成与seen查找不是免费墙钟工作；它们不消费新的完整评价额度，也不给算法提供未记账的新布局反馈。

主预算`Q_start ≤ 12`，固定生成提案上限`Q_gen ≤ 10000`，三者统一。第10000个提案仍按准入规则处理，但不得生成第10001个；在评价/时间额度用尽后不再拉取下一提案。任一上限、候选流耗尽或搜索截止到达就停止，分别标记原因；不得空转填充时间或对有限流补随机候选。完整排样评价失败时保留已完成的下界和取证，但该臂不满足等成功次数比较资格。

**与旧结果的区别：**现有扫描接口未使用此共同去重层，可能把已知H或等价原始提案计为一次重放。本协议保留其原始候选顺序，但统一准入会改变实际准入序号。因此必须保存“原始提案序号→准入评价序号”映射，另行回归验证，不能直接复用旧12次结果或称新协议与旧接口逐调用完全一致。之前“缓存复用不花额度”的口径也不能不加区分地搬到本协议。

## 5. 时限、执行顺序与冻结清单

拟议先导：每臂30 s全流水线，3 s收尾保留，38 s父进程watchdog，8 s有界清理纳入watchdog。输入读取、初始化、候选生成、查重、部分工作、完整评价、验证、审计、摘要、序列化与文件哈希均计时；进程启动受父watchdog约束。只共享最大时限，不要求各臂用满30 s。

单机依次运行，不并行抢CPU。固定计划种子20261115，对初始列表`["SINGLE", "INSERT", "KENDALL-E"]`用记录版本的Python `random.Random(20261115).shuffle`一次；本轮得到的拟议顺序为`KENDALL-E→SINGLE→INSERT`，实际运行manifest须一致并记录运行索引、Python版本与机器状态。确定性参照不靠多seed伪造独立订单。未来M加入时需形成新完整区组并重新冻结顺序，不在已有结果后挑选插入位置。

执行前manifest必须包含：准确实现提交与生产源码哈希、三臂生成器/准入/审计代码哈希、全部传递依赖、订单文件与请求哈希、配置、初始协议、预算、生成上限、最终schedule、分析规则与预定失败处理。所有旧结果文件先建立哈希清单。禁止选择性重跑、看到结果再改并列排序/额度/参数，或用历史见证替代同期控制。

本轮不扩展到178/2416件、额外seed或正式样本。后续独立订单验证须另定未用于开发的订单集合和停止准则；在此之前不做跨订单总体优势或显著性声明。

## 6. 评价终点和创新资格

主终点为**第12次完整新序列评价后的最好板数**，同时报告净利用率。资格要求各臂两次初始化完成，`Q_start=Q_complete=12`、状态一致、全部几何有效、输出和进程在时限内正常完成。任何臂失败/不足12次，该完整区组的等次数结论为不确定；保留其它臂实际结果，不将其改写成有效胜利。耗尽候选也如实记为不足，不补额外序列。

同一份轨迹输出q=`1,2,4,8,12`的最好板数；它们不是五次独立试验。q=12是唯一主终点，其余只作描述，不能事后选最有利预算宣传获胜。

效率目标在运行前固定为`N_target=N0-1`，不是看到结果后选一个双方恰好相等的质量。报告每臂首次达到该目标的准入评价序号与原始生成序号，以及完整流水线时间。十二次内未达到标为右删失`>12`，不赋值13或无穷后计算均值/倍数；若只有一个达到，只报告“唯一在额度内达到”，不编造加速比。

未来M的本订单资格判定：

- **材料增益信号：**M在q=12的板数严格低于三个同期有效参照中的最小板数，至少省一张；U增量按同订单名义总面积推导。
- **评价效率信号：**M最终板数不差于最强参照，且M与至少一个参照均达到预定目标时，M首次达标次数严格少于已达标参照中的最小次数。未达标参照保留删失，不能删掉只报最弱控制。
- 全部持平或更差，不主张新增收益；只有次级评分改善不算材料利用率提高。只胜一个弱参照、却输给简单扫描或另一个序列参照，不满足上述增益资格。

这些只是已知订单的筛查信号，**不是现有正式质量门槛的替代，也不是方法新颖性或普适有效性证明。** “创新成立”仍需清晰的新机制、近邻差异及预注册独立订单上的节材/效率证据；保持有限前缀、加缓存或改名字不自动满足。

## 7. 最低取证与失败保存

每个提案记录方法、原始序号、生成参数（i/j或a）、完整UID序列摘要、准入/重复原因、Q计数及阶段时间；大向量可用稀疏表示但须可重建。每次准入保存完整序列、未舍入布局、各板身份、完整评分、板数、净U、缓存计数与状态。另记录实际位移、Kendall距离、前置件数以及实际触及的H位置，不能用宏动作深度替代零件数。

保留两份初始布局、十二份完成布局及最终布局，共每臂15个逻辑几何审计记录（重复最终布局仍明确计数）。实际数量不足时按真实记录报告。独立审计应重建源身份/名义尺寸/旋转/刀具包络/评分/序列和布局摘要，确认最后结果等于所有已完成候选与共同初解的最好完整结果。完整候选在关闭时选优，不再增加重放。审计阶段禁止构造求解器、候选生成及解码。

此前报告的通用冗余元数据校验缺口必须在本协议实现前补齐回归：case_id、geometry_semantics、tool_diameter、最终指纹及规范化证据副本都要与原始请求/布局绑定，不能仅靠执行者本次额外检查。

失败不等于没有记录：保存已存在checkpoint及其哈希，独立审计失败运行的所有可用完整布局；watchdog后按预定运行索引恢复文件绑定，仍标为无效。拒绝未列入计划的额外文件。若绝对截止后不能新导出，保留可用计数并注明原始布局不可得；不得延长截止重建布局。所有失败、损坏记录、停止原因和有效/无效判定进入汇总。
