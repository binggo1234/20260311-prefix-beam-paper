# 有界启动联合前缀：启动通过，当前效果未通过

2026-11-26，接续[全量缺件类型重合预试验](joint-failure-overlap-pilot-20261126.md)。**当前交错窗口版本不接入默认算法，不追加窗口/种子/权重来挽救结果。** 在同一个暴露公开算例上，启动从等待100份单件反馈改为2份之后即进入两件搜索，但未优于更简单的直接随机两件访问。

后续：[冻结跨公开实例验证](public-feedback-validation-results-20261126.md)已完成10例90次运行，当前版本仍未提供相对直接随机的净增量，已关闭本版本增益主张；本页保持开发单例的历史记录。

## 本轮具体改动

仅新增私有研究原型，没有修改生产算法、配置、工厂数据或Word主稿。

- 不先扫全n个单件。逐个均匀无放回抽取UID，取得单件目标容量反馈后，最多尝试两次联合前缀，再取得下一条反馈。
- 活跃窗口固定FIFO16个签名；只在窗口内按原缺件类型重合g排序，单件分数变差不剔除。窗口不必填满才开始搜索。
- 同窗口参照忽略g，只按同一个种子化哈希优先级选对；它不是每次重新均匀抽样。
- 直接随机参照用虚拟Fisher–Yates在n(n−1)个有序对索引中均匀无放回抽取，不生成全n²表。
- 完整词仅在实际解码时构造。固定H、深度<=2时用完整词前两项标识去重；不属于该族的普通初解不混入此键空间。普通初解不能供应缺件反馈。

16是活跃窗口上限，**不是总探测上限或全部内存上限**。全局已试键、单件缓存和日志仍占空间；本批交错运行最多在线探测86个单件。每条完整扫描仍可能随订单变大而变贵，常数启动次数不等于常数时间或千件订单已验证。

## 冻结对照

仍为已暴露CLASS07，100件、100×100板、固定方向、零修边/刀缝。实际重放相同Greedy/H初解并逐项匹配旧布局，初解28张、目标27张。所有组使用同一目标容量扫描接口，每条从空布局和空解码器开始。前缀仍最多两件，无坐标重排或额外修复。

三组各用种子1000、1001、1002，共9次；总评价启动上限256，包含2次初解、每次单件探测及两件尝试。每次30秒总上限、搜索27秒、收尾3秒，父级35秒看门。找到首个全部交付、几何合格的27张布局即停。规则、M=16、每条反馈最多2次联合尝试、次序和依赖在新结果前本地冻结；不是外部预注册。

## 如何解释

启动验收通过，**当前整体效果验收未通过**。重合评分在同窗口内有一个额外成功种子，但直接随机三个种子均成功；重合组只在种子1000更省评价，其他两个更差。不能仅展示9次的最好结果，也不能把更早进入搜索等同利用率提高。

本批直接抽样与旧整表shuffle同为均匀无放回，随机数使用方式不同，同种子的路径并不相同。因此旧全量版的3/3与旧随机1/3仍是当时事实，但不能混用其路径/时长来隔离本次窗口改造的效果。新批次提醒我们：单例三个固定路径的正信号不足以建立稳定增量。本轮同时改变了交错、探测次序、窗口及破同分方式，没有证明其中哪一组件单独导致效果变化。

27张已有旧见证；本例28张净利用率84.269286%、27张87.390370%。本轮没有刷新最好板数。工厂无纹理限制、修边5、刀径6口径保持，没有工厂新运行、工业利用率或制造验证结论。也没有与生产共享缓存的SINGLE/PAIR/ASH整体作端到端比较。

## 处置与下一项

冻结本版FIFO16/每条反馈2次尝试，停止将其作为已有效主方法推进，不加种子或调窗口挽救。保留无需全量建表的直接随机两件访问作为后续强参照，仍不将标准随机抽样包装为创新。

下一项应在未参与本机制选择的公开算例上检验冻结参照与反馈机制的真实增量；先保证比较的评价/时间账本完整，再决定是否继续研究反馈或进入工厂订单。当前主题保持受限前缀，**具体独立创新和工业增量的缺口尚未关闭**。
