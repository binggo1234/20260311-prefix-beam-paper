# 工厂输入尺寸口径：Fleng模型与XML切割字段不能直接等同

2026-11-26后续核查。**目前81次工厂来源数据实验，是基于`Fleng/Fwidth`的名义矩形模型对照。它没有自动建立对工厂实际下料尺寸、轮廓和修边语义的验证。** 原方法之间的数值比较保留；其制造解释需要收窄。工厂确认的不考虑纹理、修边5毫米、刀径6毫米数值不变。

## 已核实的具体差异

现有`formal_batch.load_packing_parts`读取`Upi/Fleng/Fwidth`，将`Fleng/Fwidth`传入`PackingPart.nominal_width_mm/nominal_height_mm`。此前将它直接解释为本次工厂下料件尺寸，尚缺少与已有工厂加工结果的字段对应验证。

只读核查全部27份输入、39267行，35877行的`Fleng/Fwidth`与`RawLength/RawWidth`尺寸对不同，长宽互换视为同一对。两组字段均来自同一行，并非更换订单或丢失身份。

直接匹配的12份工厂XML中，9份可解析，另3份为空文件。9份中共有18016个`Workpiece`，`WorkpieceId`与输入`Upi`逐件、多重集匹配，数量均为1。按闭合五点、四个角点、零圆弧角和轴对齐正交边严格识别17147个矩形轮廓；其余869个暂不归为该类，不能未经处理当作同类矩形见证。

| 矩形件字段核对 | 数量 |
| --- | ---: |
| 识别出的轴对齐矩形件 | 17147 |
| XML `CutLength/CutWidth`等于输入`RawLength/RawWidth`，允许互换 | 17147 |
| XML `CutLength/CutWidth`也等于输入`Fleng/Fwidth`，允许互换 | 1403 |

独立使用Decimal重新核对以上数量和源文件绑定。另一个可观察关系是：上述17147个矩形的XML轮廓坐标包围盒，在两轴上均比`CutLength/CutWidth`多6毫米。它与工具包络表示相容，**不能把轮廓包围盒尺寸、XML切割字段和成品字段直接当成同一个量**。

因此可以确认输入模型与XML切割字段之间存在系统性的尺寸角色差异。不能仅根据字段名称或板数更少，进一步声称某份XML已经满足当前修边/工具包络模型，也不能直接把工厂软件板数当成相同约束下的胜出结果。

## 修边与刀缝的另一个语义边界

当前代码把请求尺寸每轴增加6毫米形成包络；输出名义坐标时向包络内部偏移3毫米，同时要求包络位于5毫米修边后的板内。因此当前请求矩形边到原板边至少8毫米：5毫米约束在包络上，8毫米是推导出的名义边界距离。

若制造要求中的修边5毫米约束的是工件边而非完整工具包络，两种定义将不同；本次没有足够证据替换该语义。工厂XML的边界设置也未整体核准，不能通过观察更靠边的个别轮廓就宣布当前定义错误。数值5、6及既有默认配置保持，语义核准与尺寸角色核准分别处理。

## 对原结果的修正范围

- 5381／5365／5363／5364张及相应利用率，继续是同一`Fleng/Fwidth`输入模型下的可复核结果。三臂来源一致，不能因本核查把其方法间比较说成无效。
- 这些数字暂不升级为对实际工厂毛坯下料的制造验证，亦不能直接与XML软件输出板数作公平性能比较。
- 28／95／371张旧见证继续按原输入字段与协议解释，不覆盖历史记录；它们对采用其他尺寸角色的新请求不构成直接可行性证明。
- 本次没有求解、重排或算法修改，未发现或宣称新的材料增益和新算法贡献。原始数据、主稿及既有执行记录不变。

## 当前工作取舍和明确下一步

当前简单扫描、两件扫描和ASH固定为基线。停止把追加排序、静态评分、重复旧修复机制或补对照本身当作方法创新推进；独立算法机制缺口仍在。

下一项实现限于**显式尺寸角色的数据契约**：分别保存成品/名义字段、矩形下料字段及刀具包络，不再隐式混用；新增下料角色适配时使用独立请求与结果标签，旧入口不静默替换。布局几何和产品净面积指标分开记录，不能通过换利用率分子制造提升。所有零件身份和数量保持；非矩形及边界语义不通过跳过零件或自行放宽约束解决。

该契约经来源与几何检查后，先做小范围资格验证，再重建制造口径下的强基线。**尺寸适配尚未实现，本轮没有新排样。** 这属于实验有效性工作，不能充当论文创新。后续只有提出明确机制、解释与已有方法的差异并通过强参照，才有新的算法贡献；本核查没有解决该缺口。
