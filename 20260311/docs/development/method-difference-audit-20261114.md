# 受限前缀的近邻方法差异审查（2026-11-14）

**结论：现有实现尚不足以支撑独立算法创新。** 短前缀＋固定补全可精确嵌入既有优先级决策向量框架；非断头、多板整单、序列搜索也已有直接近邻。可保留的研究问题是：硬性限制前置决策数，能否以更少完整评价发现节材解。它尚待机制和对照证据支持，不能写成已经成立的贡献。

本轮是定向方法核查，不是穷尽性新颖性审查或系统综述。生产源码、配置、测试与脚本冻结于 `f8e8fbf253ca7c94cbc85cc1b75d9806534d99cd`；没有排样运行、新订单、新启发式或实验矩阵扩展。

## 2. 与现有代码的精确对应

固定基序列H、唯一零件身份集合I，给互不重复的前缀P，现有表示为：

`S(P) = P ++ H(I \ set(P)), |P| <= K`。

[single_prefix_scan.py](../../src/inrp/single_prefix_scan.py)目前只扫描K=1：依既有入口顺序选一个UID前置，其余按短边顺序保序；[ordering.py](../../src/inrp/ordering.py)定义确定性破同分。它是有限前缀族的一个具体访问策略。当前复杂搜索还包含多件宏动作和多种补全模式，不能将宏动作深度直接当作这一定义中的K，也不能把所有叶节点说成固定H的成员。

BubbleSearch用决策向量a表示第i步选“当前剩余队列中第a_i个元素”。对固定H，我们的族**恰好**对应：前K个坐标合法自由选择，之后所有坐标为1。任给P可依次取出指定元素；之后每次取队首，正好保持剩余H。反向也成立。这是本轮依据定义推导的表示关系，不是文献提出了我们当前选件/预算策略的证明。

两个限制仍有可描述的差别：

- 硬前缀限制控制自由坐标的位置和数量；Kendall限制控制总逆序对数。H=`1234`、P=`4`得到`4123`：K=1，但Kendall距离为3。
- 一般一次插入邻域可在中间移动一个元素，例如`1234→1324`；这个结果不属于K=1的仅前置族。因此前置族是一般单件重定位邻域的受限子集，不能把它说成全新的序列变换。

族的序列数量也要准确：对n个唯一身份，`|F_{<=K}|=n!/(n-K)!`，0≤K≤n。较短前缀的结果可通过追加剩余队首扩展到长度K，因此各长度并非不相交，不能将`sum(n!/(n-k)!)`当作不同完整序列数。这个计数只是基本组合性质，不作为创新贡献。

本地独立、无求解器导入的验证枚举n=1…7，共核对16071个前缀，检查两种表示、族嵌套与计数，并检查上述反例。有限枚举是推导的实现核验，不替代理论论证，也没有产生新的材料利用率证据。

| 缓存、延迟构造就是主创新 | 继续归入工程支撑。其真实提速保留，不能替代算法贡献。 |

## 4. 下一项交付与停止条件

**保留受限前缀主题与简单扫描强基线，撤下“仅凭这一表示即有新算法”的叙述。** 当前适合研究的问题是硬前缀预算下的覆盖效率，而不是再增加宏动作或更长搜索。

下一项应先形成一个**同一解码器下的序列方法参照协议**：明确一般单件插入与Kendall/BubbleSearch式访问如何覆盖现有前缀族，统一初解、几何、完整评价预算、总时限和失败判据。已有文献算法作为参照，不作为新增主方法；本轮不安装、不实现、不运行该参照，不扩大矩阵。不能简单宣称“随机搜索表示不了我们的前缀”。

只有提出一个具体的、区别于已有框架的访问/安全剪枝机制，并在上述强参照下证明节材或达到同等节材所需评价更少，才考虑算法贡献。若差异仅剩应用配置、表示命名和缓存优化，应按工程应用贡献定位，不能继续以新增启发式制造创新感。递归Pilot全文的关键限制关系未解决前，不声称完成全面新颖性排除。
